# 真机验证计划

## 使用方式

软件开发阶段只进行代码审查和 ARM 交叉编译。待相关功能的软件实现完成后，再集中下载到 C 板执行本文件中的真机验证；每次验证记录实际现象、结论和异常处理。

测试代码不得无条件写入主循环。需要发送测试报文或控制外设时，应使用经审核的临时测试开关，并在验证后决定是否保留。

## I2C3 上拉与设备通信

### 前提

- 固件包含当前 `board.ioc` 与 `i2c.c` 的 I2C3 配置；
- PA8 连接 I2C3_SCL，PC9 连接 I2C3_SDA；
- 已确认待测 I2C 从设备的供电、电平和 7 位地址。

### 操作

1. 断电检查 SDA、SCL 没有短路到地或电源。
2. 上电后测量两根线的空闲电平；必要时用示波器观察上升沿。
3. 下载经审核的 I2C 地址扫描或指定寄存器读取测试程序。
4. 读取目标设备的已知寄存器，并记录应答与返回值。

### 预期现象

- 总线空闲时 SDA、SCL 均为高电平；
- 设备地址阶段收到 ACK；
- 读取到的已知寄存器值与器件手册一致；
- 400 kHz 通信下没有持续 NACK、总线忙或明显的上升沿过慢现象。

## CAN 最小安全发送

### 前提

- 固件已包含 `CAN_Init()` 与 `CAN_Transmit()` 的当前实现；
- CAN1 或 CAN2 连接 USB-CAN、另一块 CAN 节点或具备监听能力的设备；
- 总线两端各有 120 Ω 终端电阻，CANH/CANL 连接正确，并具有可靠共地；
- 已准备经审核的临时测试入口，以受控方式发送一帧标准数据帧。

### 操作

1. 断电完成 CANH、CANL、GND 与终端电阻检查。
2. 上电后将监听设备设置为 1 Mbps，标准帧监听模式。
3. 下载含临时测试入口的固件，调用 `CAN_Init()`，再发送一帧已约定的标准数据帧。
4. 在监听设备上记录标准 ID、DLC、八个数据字节和发送次数。
5. 分别尝试非法 ID、DLC 大于 8、空数据指针和发送邮箱满的情形，确认不会出现额外有效报文。

### 预期现象

- 监听设备收到 1 Mbps 的标准数据帧；
- ID、DLC 与数据字节顺序同测试入口设定一致；
- 合法调用返回 `HAL_OK`，表示报文已进入 CAN 发送邮箱；这不单独证明总线上已有其他节点应答；
- 合法发送后 CAN 控制器没有持续错误帧或 Bus-Off；
- 非法输入或未完成初始化时返回 `HAL_ERROR` 且不出现新的发送报文；邮箱无空闲位置时返回 `HAL_BUSY`。

### 接收回调验证

1. 注册一个只记录 CAN 句柄、标准 ID、DLC 与数据字节的临时接收回调。
2. 使用监听设备向 C 板的 CAN1 或 CAN2 发送一帧标准数据帧。
3. 通过断点、串口输出或受控内存变量确认回调只执行一次，并检查接收内容。

预期现象：HAL 的 RX FIFO0 中断触发后，注册回调收到与发送端一致的 CAN 句柄、标准 ID、DLC 和数据字节；扩展帧与远程帧不会交给该回调。

## UART 发送

### 前提

- 固件已包含 `USART_Transmit()` 的当前实现；
- 待测 USART 已完成 CubeMX 生成的初始化；
- 串口适配器使用 3.3 V 逻辑电平，与 C 板可靠共地；
- 串口适配器 RX 接 C 板 TX，串口参数设为 115200、8 数据位、无校验、1 停止位。

### 操作

1. 使用经审核的临时测试入口，分别通过 USART1 和 USART6 发送已知字节序列。
2. 对阻塞、DMA 和中断三种发送方式分别重复测试。
3. DMA 或中断发送后，保持发送缓冲区不被修改，直到 HAL 发送完成回调发生。
4. 在串口工具中记录接收字节、发送次数和是否出现乱码或截断。

### 预期现象

- 串口工具收到的字节顺序与发送缓冲区一致；
- 三种发送方式均不出现乱码、丢字节或额外字节；
- 阻塞发送返回 `HAL_OK` 时字节已发送完成；DMA/中断发送返回 `HAL_OK` 只表示传输已启动，仍需等待发送完成回调；
- 空指针、零长度、未知句柄和未知模式不会产生发送数据；
- DMA 与中断发送期间，发送缓冲区保持有效时传输正常完成。

## UART 通用 DMA 接收

### 前提

- 调用模块为 USART1、USART6 分别准备独立且持续有效的接收缓冲区；
- 已注册只记录 UART 句柄、事件类型和写入位置的短回调；
- 串口适配器使用 3.3 V 逻辑电平并与 C 板可靠共地。

### 操作

1. 分别注册 USART1 和 USART6 的回调，并调用 `USART_Receive()` 启动接收。
2. 向其中一路发送一段已知字节，然后暂停发送以触发空闲事件。
3. 用断点或受控调试变量记录回调中的 UART 句柄、缓冲区地址、事件类型和写入位置。
4. 对另一路重复，确认两路接收状态互不覆盖。

### 预期现象

- 回调收到正确的 UART 句柄和调用模块提供的缓冲区地址；
- 空闲事件的写入位置与实际发送字节数一致；
- DMA 半传输、全传输和空闲事件可由回调中的事件类型区分；
- BSP 不解析设备协议，回调中不执行阻塞操作或长时间计算。

## PWM 舵机与加热

### 前提

- 固件已包含当前 `PWM_Start()`、`PWM_Stop()`、`PWM_SetPeriod()` 和 `PWM_SetDutyRatio()` 的实现；
- 已准备经审核的临时测试入口；
- 首先使用示波器或逻辑分析仪观察 PC6（TIM8_CH1）和 PF6（TIM10_CH1），不直接依赖舵机或加热电阻判断波形；
- 对加热电阻的带载测试已确认供电、散热和温度保护措施。

### 操作

1. 对 TIM8_CH1 调用 `PWM_SetPeriod(&htim8, 0.02f)`、`PWM_SetDutyRatio(&htim8, 0.075f)` 和 `PWM_Start(&htim8, TIM_CHANNEL_1)`，观察 PC6。
2. 将 TIM8 周期改为 0.01 秒，确认高电平时间与周期按相同比例变化；再调用 `PWM_Stop()`，确认 PWM 翻转结束。
3. 对 TIM10_CH1 保持默认周期，依次设置 0%、10% 与 50% 占空比后启动 PWM，先只在 PF6 观察波形；带载测试须另行审核。
4. 分别传入空指针、未配置的定时器、错误通道、零周期、超出范围的周期和小于 0 或大于 1 的占空比，记录返回状态并确认波形未意外改变。

### 预期现象

- TIM8_CH1 在 PC6 输出 20 ms 周期（50 Hz）、约 1.5 ms 高电平的 PWM；
- TIM8 周期改为 10 ms 后，原来的 7.5% 占空比保持不变，高电平约为 0.75 ms；
- TIM10_CH1 在 PF6 输出约 33.6 kHz 的 PWM，设置的占空比与示波器测量结果一致；
- 无效输入返回 `HAL_ERROR`，不会修改原有 PWM 配置或启动额外输出。

## BMI088 SPI 通信与 Chip ID

### 前提

- 固件已包含 `cBMI088` 的当前 SPI 寄存器读写和 Chip ID 校验实现；
- SPI1 已由 CubeMX 初始化为 BMI088 所需模式，且 PA4/ACC_CS、PB0/GYRO_CS 的空闲电平为高；
- BMI088 的供电、地、SCK、MOSI、MISO 和两个片选引脚已按板级连接确认；
- 已准备经审核的临时测试入口；本项不调用温控或加热 PWM。

### 操作

1. 上电后确认 ACC_CS 和 GYRO_CS 均保持高电平，未同时选中两个芯片。
2. 在临时测试入口创建 `cBMI088` 对象，依次调用 `VerifyAccChipID()` 与 `VerifyGyroChipID()`。
3. 使用断点、串口输出或受控调试变量记录 `self_test.ACC_CHIP_ID_ERR`、`self_test.GYRO_CHIP_ID_ERR` 和 `self_test.INIT_ERR`。
4. 使用逻辑分析仪分别观察两次读取：加速度计读取应在命令后额外时钟一个无效字节；陀螺仪读取不应有该额外步骤。

### 预期现象

- 加速度计读到 Chip ID `0x1E`，陀螺仪读到 Chip ID `0x0F`；
- 两个 Chip ID 错误标志和 `INIT_ERR` 均为 `false`；
- 每次读写期间只有目标片选拉低，结束后目标片选恢复高电平；
- SPI 超时、接线错误或 ID 不匹配时，对应 Chip ID 错误标志和 `INIT_ERR` 为 `true`，不会被误判为初始化成功。

### 三轴数据与温度

1. 在 Chip ID 校验成功且 `Config()` 完成后，使用经审核的临时测试入口分别调用 `ReadAccData()`、`ReadGyroData()` 和 `ReadAccTemperature()`。
2. 将 C 板静止放在水平桌面，记录加速度三个分量、三轴角速度和温度；再缓慢改变板子的朝向，观察加速度分量变化。
3. 保持板子静止至少 2 秒后再次读取温度，确认温度读数按 BMI088 的更新周期稳定变化。

预期现象：

- 加速度数据单位为 `m/s²`，静止时三个分量的合量接近一个重力加速度，具体落在哪个轴及正负方向取决于安装方向；
- 角速度数据单位为 `rad/s`；标定前允许存在静止零偏，静止时不应出现持续的大幅跳变；
- 温度单位为 `°C`，在 BMI088 工作范围 `-40 °C` 到 `85 °C` 内；温度寄存器约每 1.28 秒更新一次；
- 读取接口通信失败时会清零本次输出；调用 `VerifyAccData()` 或 `VerifyGyroData()` 后，对应数据错误标志应为 `true`。

### 数据有效性与陀螺仪标定

1. 传感器正常连接时，先分别读取加速度和角速度，再调用对应的 `Verify...Data()`；记录两个数据错误标志。
2. 在经审核的临时测试入口中模拟一次 SPI 读取失败，例如断开传感器供电或使目标片选无法得到响应；再次读取和校验，随后恢复正常连接。
3. 将 C 板完全静止放置，调用 `Calibrate()`；当前实现采集 4000 次，每次间隔一个 ThreadX tick，因此 1000 Hz tick 下约需 4 秒。
4. 标定完成后保持静止，再读取角速度；记录标定错误标志、三个零偏结果和静止角速度。
5. 可选地在标定期间施加明显且单向的旋转，确认平均零偏超过当前 `0.1 rad/s` 上限时标定失败且保留原零偏。

预期现象：

- 正常读取且三个分量均为有限值时，`ACC_DATA_ERR` 与 `GYRO_DATA_ERR` 为 `false`；
- SPI 读取失败后，对应读取函数输出为零，且对应数据错误标志为 `true`；
- 静止标定成功时，`CALIBRATE_ERR` 为 `false`，后续静止角速度接近零；
- 标定期间读取失败或平均零偏任一轴超过 `0.1 rad/s` 时，`CALIBRATE_ERR` 为 `true`，并保留标定前的零偏；
- 当前标定仅检查通信与平均零偏上限，尚不以方差或振动幅度判断“是否绝对静止”；该阈值将在获得真机数据后另行确定。

### 温度闭环与加热电阻

**目的：** 验证 BMI088 内置温度读取、`TemperatureControl()` 的加热方向，以及 TIM10/PF6 对加热电阻的 PWM 输出。

**安全前提：** 固定机器人并确保加热电阻周围无易燃物；首次测试从短时间、低目标温度差开始，同时用独立温度计或热成像确认升温情况。未确认硬件接线和供电前，不执行本项测试。

| 步骤 | 操作 | 预期现象 |
| --- | --- | --- |
| 1 | 读取 BMI088 温度并记录初始值 | 温度值合理且连续，不应固定为 `0.0 °C` |
| 2 | 调用 `TemperatureControl(当前温度 - 5 °C)` | PWM 占空比为 `0`，加热电阻不升温 |
| 3 | 调用 `TemperatureControl(当前温度 + 5 °C)` | PWM 输出非零；加热电阻开始升温 |
| 4 | 持续记录温度和 PWM 占空比 | 接近目标温度后占空比下降；不会持续满功率加热 |
| 5 | 断开 BMI088 通信或人为制造温度读取失败 | `TEMP_CTRL_ERR` 置位，函数请求 PWM 占空比归零 |

**判定说明：** 当前 `kp=0.1`、`ki=0`、`kd=0` 仅使软件闭环可运行，不代表已完成实际热系统整定。真机测试后再根据升温速度、超调和稳定误差调整 PID 参数。

## M2006 CAN 反馈解析

### 前提

- 固件已包含当前 `DJIMotorHandler` 与 `M2006` 的实现，且经审核的临时测试入口已创建一个 `M2006` 对象；
- 已确认电调为 C610、CAN 波特率为 1 Mbps，且电机实际 ID、CAN1/CAN2 接线与临时测试入口一致；
- 机器人固定并断开任何可能的控制输出。本项只观察电调反馈，不发送电机电流命令。

### 操作

1. 调用 `registerMotor(&motor, &hcanX, 0x20Y)`，其中 `X` 和 `Y` 必须与实际总线和电调 ID 一致。
2. 在 CAN 接收分发入口中，仅将标准帧 `0x201~0x208` 映射为 `updateFeedback(&hcanX, data, StdId - 0x201)`；本批不在 BSP 内直接注册该分发入口。
3. 通过断点或受控调试变量记录 `motorFeedback.ecd`、`speed_rpm`、`speedFdb`、`positionFdb`、`currentFdb`、`temperatureFdb` 与 `AliveFlag`。
4. 手动缓慢正反转输出轴，并特别跨过编码器计数由 `8191` 到 `0`、或由 `0` 到 `8191` 的边界，观察连续位置变化。

### 预期现象

- 每次收到对应 ID 的 8 字节反馈帧，`AliveFlag` 增加，编码器、转速、电流和温度与电调反馈一致；
- 第一次反馈只建立零位，`positionFdb = 0 rad`；后续正反转时位置连续，不会在编码器回绕处跳变约一圈；
- `speedFdb` 的单位为输出轴 `rad/s`，已按 M2006 的 `36:1` 减速比换算；
- 未注册 ID、空数据、错误总线或非 `0x201~0x208` 的报文不应修改任何已登记电机；
- 本项不发送 `0x200` / `0x1FF` 控制帧，电机不应因本项产生转动或电流输出。

## M2006 CAN 控制帧

### 前提

- 已完成上一节的反馈验证，并在经审核的临时测试入口中显式设置某台已登记电机的 `currentSet`；
- 已确认 C610 与 M2006 的供电、CAN 总线、实际 ID 和机械固定状态；
- 初始测试只使用小幅、短时的电流指令，并具备随时断电的条件。

### 操作

1. 调用 `CAN_Init()` 后，登记一台 ID 为 `0x201` 的 M2006，并将其 `currentSet` 保持为 `0`；调用 `sendControlData()`，记录返回状态和总线报文。
2. 设置 `currentSet = 1000`，再次调用；检查 CAN1 或 CAN2 上出现 ID `0x200`、长度为 8 的标准数据帧，前两个字节为 `0x03 0xE8`，其余字节为零。
3. 设置 `currentSet = -1000`，确认前两个字节为 `0xFC 0x18`，验证负数采用二进制补码的大端序发送。
4. 将 `currentSet` 设置为大于 `maxCurrent` 的值，确认发送值被限制为 `maxCurrent`；再设置为零，确认发送帧对应槽位回到 `0x00 0x00`。
5. 为 `0x205` 登记另一电机并设置小值，确认其数据进入 ID `0x1FF` 的前两个字节；随后才逐步验证其他槽位的字节位置。

### 预期现象

- ID `0x201~0x204` 的四台电机使用 `0x200`，ID `0x205~0x208` 的四台电机使用 `0x1FF`；每个报文恰好为 8 字节；
- 一台电机占连续两个字节，槽位顺序与 ID 顺序一致；未登记槽位始终为零；
- `sendControlData()` 返回 `HAL_OK` 表示帧已提交给 CAN 外设，`HAL_BUSY` 表示发送邮箱满，`HAL_ERROR` 表示 CAN 未初始化、参数或状态异常；
- 先确认总线报文完全正确，再观察小电流下的电机方向；若方向与期望相反，应停止测试并确认接线、减速机构方向和控制坐标约定后再修改上层目标方向，不应直接更改协议字节序。

## M2006 控制模式与在线保护

### 前提

- 已完成 CAN 反馈解析和控制帧字节序验证，且由经审核的临时测试入口周期性调用 `updateFeedback()`、`setOutput()`、`sendControlData()` 与 `AllMotorAliveCheck()`；
- 已根据实际电机、负载和控制周期完成 PID 参数整定，初次测试从松弛和小速度指令开始；
- 机器人固定，具备独立断电条件，位置环测试前先确认速度环方向正确。

### 操作

1. 设置 `RELAX_MODE`，即使 `speedSet`、`positionSet` 曾有非零值，也检查 `currentSet` 和对应 CAN 槽位均为零。
2. 仅完成速度 PID 参数整定后，设置 `SPD_MODE` 和小的正、负 `speedSet`，记录 `speedFdb`、`currentSet` 和实际转向；确认速度接近目标且反向指令方向相反。
3. 在速度环方向正确后，完成位置 PID 参数整定，设置 `POS_MODE` 与一个小的相对目标位置；记录 `positionFdb`、位置 PID 输出、速度 PID 输出和 `currentSet`。
4. 保持电机通信正常，连续两次调用 `AllMotorAliveCheck()`，确认电机在线；然后停止向该电机发送反馈帧，再次检查。

### 预期现象

- 松弛模式清空 PID 历史并发送零电流；
- 速度模式中，目标速度与反馈速度的误差经速度 PID 转换为受 `maxCurrent` 限制的电流命令；
